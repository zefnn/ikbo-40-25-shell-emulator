# Эмулятор командной строки (ИКБО-40-25, Вариант №10)

Учебный проект по дисциплине «Конфигурационное управление».
Эмулятор командной строки UNIX-подобной ОС с графическим
интерфейсом и виртуальной файловой системой (VFS). Разработка
ведётся поэтапно; текущее состояние соответствует **Этапу 5
(дополнительные команды)**.

## Общее описание

Приложение — REPL-прототип с GUI на Tkinter: пользователь вводит
команды в поле ввода, эмулятор разбирает строку на имя команды и
аргументы (с поддержкой аргументов в кавычках) и выводит результат
в область прокрутки, имитируя диалог в терминале. Эмулятор
настраивается через параметры командной строки и/или YAML-файл
конфигурации, каждый вызов команды пишется в XML-лог, а с Этапа 3
дополнительно загружает в память виртуальную файловую систему
(VFS) из CSV-файла, а с Этапа 4 команды `ls`, `cd`, `cat`, `tail`,
`clear` работают над этой VFS так же, как в настоящем терминале, а с
Этапа 5 команды `mkdir` и `mv` изменяют её — только в памяти.

## Функции и настройки

### Этап 1 — REPL

- **GUI-окно** (Tkinter) с областью вывода (scrollback) и полем
  ввода. Заголовок окна содержит имя VFS (basename пути `--vfs`,
  если он задан).
- **Парсер команд** (`shellemu.parser`) — собственная реализация
  на основе посимвольного разбора строки (без сторонних библиотек
  парсинга), корректно обрабатывающая аргументы в одинарных и
  двойных кавычках.
- **Команды-заглушки** `ls`, `cd` — на этом этапе выводили своё имя
  и разобранные аргументы (с Этапа 4 это настоящие команды).
- **Команда `exit`** — закрывает окно эмулятора.
- **Обработка ошибок**: неизвестная команда →
  `<имя>: command not found`; некорректный синтаксис аргументов
  (например, незакрытая кавычка) → `parse error: <причина>`.

### Этап 2 — конфигурация, логирование, стартовый скрипт

**Параметры командной строки** (`shellemu.config`):

| Флаг | Назначение |
|---|---|
| `--vfs <путь>` | физическое расположение VFS (CSV-файл) |
| `--log <путь>` | XML-файл лога событий (по умолчанию `shellemu_log.xml`) |
| `--script <путь>` | стартовый скрипт с командами эмулятора |
| `--config <путь>` | YAML-файл конфигурации |

**YAML-конфигурация** — файл, переданный через `--config`, может
задавать те же `vfs_path`, `log_path`, `script_path` (пример —
[examples/config.yaml](examples/config.yaml)). **Приоритет**:
значение из командной строки всегда побеждает значение из файла;
если ни то, ни другое не задано — используется значение по
умолчанию (сейчас это есть только у `log_path`). При ошибке чтения
или разбора YAML приложение не падает — сообщение об ошибке
выводится в транскрипт, а работа продолжается с теми настройками,
что уже удалось определить.

При запуске эмулятор всегда печатает в транскрипт отладочный блок
со всеми итоговыми параметрами (`[config] ...`).

**XML-логирование** (`shellemu.eventlog`) — каждая успешно
распознанная команда записывается в файл `--log` с меткой времени.
Лог накапливается между запусками.

**Стартовый скрипт** (`--script`) — текстовый файл с командами
эмулятора, выполняемыми последовательно при запуске; пример —
[examples/startup.txt](examples/startup.txt). Ошибочные строки не
прерывают выполнение. Если файл скрипта не читается — отдельное
сообщение `startup script error: ...`, без падения приложения.

### Этап 3 — виртуальная файловая система (VFS)

**Формат VFS** (`shellemu.vfs`) — источник VFS, как и требует
задание, это CSV-файл с ровно тремя колонками:

| Колонка | Значение |
|---|---|
| `path` | путь внутри VFS, вложенность через `/` (например, `docs/notes/todo.txt`) |
| `type` | `file` или `dir` |
| `content` | содержимое файла в base64 (для `dir` — пусто) |

Формат спроектирован самостоятельно (в задании явно оставлено «на
усмотрение»): **вложенность кодируется через путь**, а не через
отдельные колонки на каждый уровень — так можно описать сколько
угодно уровней вложенности одной и той же плоской таблицей, как в
обычном архиве tar/zip. Папки для файлов создаются автоматически
по пути (`docs/notes/todo.txt` сам по себе создаёт `docs` и
`docs/notes`); отдельная строка с `type=dir` нужна только для
**пустой** папки, которую иначе неоткуда было бы вывести. Бинарные
данные (и текстовые тоже — для единообразия) кодируются в base64,
как и предписано заданием.

**Всё в памяти** — CSV считывается один раз при запуске и
превращается в дерево объектов `VfsNode` (на `dict` с детьми у
папок); сам CSV-файл после загрузки никак не используется и не
изменяется, содержимое VFS никогда не распаковывается на диск.

**Обработка ошибок загрузки** — оба случая из задания:
- файл не найден / не читается → `VFS error: cannot read VFS
  file: ...`;
- неверный формат (несовпадающий заголовок, некорректный base64,
  путь вида `../x` или с пустым сегментом, конфликт
  файл/папка, задвоенный путь, неизвестный `type`) → `VFS error:
  ...` с конкретной причиной.

В обоих случаях приложение не падает — просто продолжает работать
без VFS. При успешной загрузке в стартовом блоке печатается
`[vfs] loaded: N files, M directories`.

### Этап 4 — основные команды

Приглашение теперь показывает текущую папку: `VFS:/docs$`
(корень VFS — `VFS:/$`). Состояние (корень VFS и текущая папка)
хранит объект `Session` (`shellemu.session`); пути разбирает
`vfs.resolve` — он ходит по настоящему дереву, поэтому `..`, `.`,
повторные слэши и ошибки (`no such file`, `not a directory`) ведут
себя как в UNIX. Без загруженной VFS команды отвечают
`<команда>: no VFS loaded`.

| Команда | Что делает |
|---|---|
| `ls [-l] [-h] [-a] [путь...]` | список папки; пути абсолютные и относительные, несколько путей сразу |
| `cd [путь]` | смена папки: `/a/b`, `a/b`, `..`, `.`, `~` и без аргумента — корень, `-` — назад |
| `cat файл...` | вывод содержимого одного или нескольких файлов подряд |
| `tail [-n N] файл...` | последние N строк (по умолчанию 10); `-n 3`, `-n3`, `-3`; для нескольких файлов — заголовки `==> имя <==` |
| `clear` | очищает экран |
| `exit` | закрывает окно |

**Флаги `ls` комбинируются в любом виде**: `-l -h -a`, `-lh`,
`-la`, `-lah`, `-hla` и т.д. дают один и тот же результат.
- `-a` — показывает скрытые (начинающиеся с точки) элементы и
  записи `.` и `..`;
- `-l` — подробный формат: права, число ссылок, владелец, группа,
  размер, дата изменения, имя, и строка `total`;
- `-h` — размеры в человекочитаемом виде (`512`, `1.5K`, `30K`);
  как и в настоящем `ls`, без `-l` ни на что не влияет.

В VFS нет прав, владельца и дат, поэтому для `ls -l` они
синтезируются: папки `drwxr-xr-x`, файлы `-rw-r--r--`, размер папки
4096, владелец — пользователь ОС, дата — время изменения CSV-файла.
Неизвестный флаг даёт ошибку (`ls: invalid option -- 'x'`).

Демонстрация: `./examples/run_stage4.sh` прогоняет
[examples/stage4_startup.txt](examples/stage4_startup.txt) — все
режимы всех команд и обработку ошибок над
[examples/vfs_stage4.csv](examples/vfs_stage4.csv) (вложенные папки,
скрытые файлы, файл с пробелом в имени, файл на 25 строк, файлы
1.5K и 30K, пустая папка).

### Этап 5 — команды, изменяющие VFS (`mkdir`, `mv`)

Обе команды правят дерево в памяти; **CSV-файл никогда не
перезаписывается** (это проверяет тест), а при следующем запуске VFS
снова загружается из исходного файла. У затронутых папок обновляется
время изменения, это видно в `ls -l`.

| Команда | Что делает |
|---|---|
| `mkdir [-p] путь...` | создаёт папки; `-p` создаёт и недостающие родительские и не ругается на уже существующую папку |
| `mv источник назначение` | переименовывает; если назначение — существующая папка, переносит в неё |
| `mv источник... папка` | переносит несколько элементов в папку |

Поведение как в UNIX:
- `mkdir`: ошибки `File exists`, `No such file or directory`,
  `Not a directory`; при нескольких операндах ошибка одного не
  мешает остальным.
- `mv`: файл перезаписывает существующий файл; папка может заменить
  только пустую папку; ошибки `cannot overwrite ... with ...`,
  `Directory not empty`, `'a' and 'a' are the same file`,
  `cannot move 'a' to a subdirectory of itself`,
  `target 'x' is not a directory`, а корень, `.` и `..` перенести
  нельзя (`Device or resource busy`).
- Если перенесена папка, внутри которой вы находитесь (или в
  которую вернёт `cd -`), сессия остаётся в ней же по новому пути:
  приглашение меняется с `VFS:/docs/projects$` на
  `VFS:/archive/projects$`.
- Разбор флагов (`-p`, `--`, неизвестные опции) вынесен в общий
  модуль `shellemu.arguments` и используется всеми командами.

Демонстрация: `./examples/run_stage5.sh` прогоняет
[examples/stage5_startup.txt](examples/stage5_startup.txt) — все
режимы `mkdir` и `mv` с ошибками — над той же
[examples/vfs_stage4.csv](examples/vfs_stage4.csv).

## Сборка и тесты

Требования: Python 3.10+, зависимости из
[requirements.txt](requirements.txt) (`PyYAML` — чтение
конфигурации; `pytest` — тесты; `tkinter` и `csv`/`base64` — из
стандартной библиотеки).

```bash
pip install -r requirements.txt
```

Запуск эмулятора:

```bash
./run.sh                                   # без параметров
./examples/run_cli_only.sh                 # все параметры через CLI
./examples/run_config_only.sh              # все параметры через YAML
./examples/run_cli_overrides_config.sh     # CLI переопределяет конфиг
./examples/run_bad_config.sh               # ошибка чтения конфига
./examples/run_bad_script.sh               # ошибка стартового скрипта
./examples/run_vfs_minimal.sh              # VFS: один файл, без папок
./examples/run_vfs_several.sh              # VFS: несколько файлов и папок
./examples/run_vfs_deep.sh                 # VFS глубиной 3 уровня + стартовый скрипт
./examples/run_vfs_bad.sh                  # ошибка формата VFS
./examples/run_vfs_missing.sh              # VFS-файл не найден
./examples/run_stage4.sh                   # Этап 4: все режимы ls/cd/cat/tail
./examples/run_stage4_clear.sh             # Этап 4: команда clear
./examples/run_stage4_interactive.sh       # Этап 4: та же VFS, ввод руками
./examples/run_stage5.sh                   # Этап 5: все режимы mkdir/mv
```

Запуск тестов:

```bash
pytest
```

Фрагмент работы с `mkdir`/`mv` (VFS `examples/vfs_stage4.csv`,
правки только в памяти):

```

VFS:/$ mkdir projects
VFS:/$ mv readme.txt projects
VFS:/$ ls projects
readme.txt

VFS:/docs/projects$ mv /docs /archive

mv: cannot move 'archive' to a subdirectory of itself, 'archive/inner'
```

Полный прогон со всеми режимами — `./examples/run_stage5.sh`.

Старые демонстрации Этапов 2–3 по-прежнему работают
(`./examples/run_vfs_deep.sh` и др.); их стартовый скрипт
[examples/startup.txt](examples/startup.txt) теперь использует
настоящие `ls`/`cd`, а ошибочные строки по-прежнему пропускаются.
