# Эмулятор командной строки (ИКБО-40-25, Вариант №10)

Учебный проект по дисциплине «Конфигурационное управление».
Эмулятор командной строки UNIX-подобной ОС с графическим
интерфейсом и виртуальной файловой системой (VFS). Разработка
ведётся поэтапно; текущее состояние соответствует **Этапу 2
(Конфигурация)**.

## Общее описание

Приложение — REPL-прототип с GUI на Tkinter: пользователь вводит
команды в поле ввода, эмулятор разбирает строку на имя команды и
аргументы (с поддержкой аргументов в кавычках) и выводит результат
в область прокрутки, имитируя диалог в терминале. С Этапа 2
эмулятор настраивается через параметры командной строки и/или
YAML-файл конфигурации, а каждый вызов команды пишется в XML-лог.
Сама файловая система (VFS) появится на Этапе 3.

## Функции и настройки

### Этап 1 — REPL

- **GUI-окно** (Tkinter) с областью вывода (scrollback) и полем
  ввода. Заголовок окна содержит имя VFS (basename пути `--vfs`,
  если он задан, иначе заглушка — реальная загрузка содержимого
  VFS появится на Этапе 3).
- **Парсер команд** (`shellemu.parser`) — собственная реализация
  на основе посимвольного разбора строки (без сторонних библиотек
  парсинга), корректно обрабатывающая аргументы в одинарных и
  двойных кавычках.
- **Команды-заглушки** `ls`, `cd` — выводят своё имя и разобранные
  аргументы, не изменяя никакого состояния.
- **Команда `exit`** — закрывает окно эмулятора.
- **Обработка ошибок**: неизвестная команда →
  `<имя>: command not found`; некорректный синтаксис аргументов
  (например, незакрытая кавычка) → `parse error: <причина>`.

### Этап 2 — конфигурация, логирование, стартовый скрипт

**Параметры командной строки** (`shellemu.config`):

| Флаг | Назначение |
|---|---|
| `--vfs <путь>` | физическое расположение VFS |
| `--log <путь>` | XML-файл лога событий (по умолчанию `shellemu_log.xml`) |
| `--script <путь>` | стартовый скрипт с командами эмулятора |
| `--config <путь>` | YAML-файл конфигурации |

**YAML-конфигурация** — файл, переданный через `--config`, может
задавать те же `vfs_path`, `log_path`, `script_path` (пример —
[examples/config.yaml](examples/config.yaml)). **Приоритет**:
значение из командной строки всегда побеждает значение из файла;
если ни то, ни другое не задано — используется значение по
умолчанию (сейчас это есть только у `log_path`). При ошибке чтения
или разбора YAML (файл не найден, некорректный синтаксис)
приложение не падает — сообщение об ошибке выводится в транскрипт,
а работа продолжается с теми настройками, что уже удалось
определить.

При запуске эмулятор всегда печатает в транскрипт отладочный блок
со всеми итоговыми параметрами (`[config] ...`), независимо от
того, откуда каждое значение было взято.

**XML-логирование** (`shellemu.eventlog`) — каждая успешно
распознанная команда (включая неизвестные — сам факт попытки
вызова) записывается в файл `--log` с меткой времени. Лог
накапливается между запусками: существующий файл дочитывается и
дополняется, а не перезаписывается с нуля.

**Стартовый скрипт** (`--script`) — текстовый файл с командами
эмулятора, выполняемыми последовательно при запуске; пример —
[examples/startup.txt](examples/startup.txt). Ошибочные строки
(неизвестная команда, синтаксическая ошибка) не прерывают
выполнение — выводятся как обычная ошибка, и скрипт продолжается
со следующей строки. На экране отображается как «ввод» (сама
строка скрипта), так и результат — так же, как при интерактивном
вводе. Если путь к скрипту указан, но файл не читается — об этом
сообщается отдельно (`startup script error: ...`), и эмулятор
просто переходит в обычный интерактивный режим.

## Сборка и тесты

Требования: Python 3.10+, зависимости из
[requirements.txt](requirements.txt) (`PyYAML` — чтение
конфигурации; `pytest` — тесты; `tkinter` — из стандартной
библиотеки).

```bash
pip install -r requirements.txt
```

Запуск эмулятора:

```bash
./run.sh                    # без параметров, значения по умолчанию
./examples/run_cli_only.sh  # все параметры через CLI
./examples/run_config_only.sh        # все параметры через YAML
./examples/run_cli_overrides_config.sh  # CLI переопределяет конфиг
./examples/run_bad_config.sh   # демонстрация ошибки чтения конфига
./examples/run_bad_script.sh   # демонстрация ошибки стартового скрипта
```

Запуск тестов:

```bash
pytest
```

## Примеры использования

После запуска в окне эмулятора отображается приглашение `VFS:~$`.
Сначала — блок отладочного вывода параметров, затем (если задан
`--script`) выполнение стартового скрипта, затем обычный
интерактивный режим. Пример сеанса (интерактивный ввод):

```
VFS:~$ ls -la /tmp
[stub] command=ls args=['-la', '/tmp']
VFS:~$ cd "My Documents"
[stub] command=cd args=['My Documents']
VFS:~$ foo bar
foo: command not found
VFS:~$ ls "unterminated
parse error: missing closing quote: "
VFS:~$ exit
```

Второй пример показывает, что аргумент в кавычках (`"My
Documents"`) распознаётся как один токен, а не как два.

Пример запуска со стартовым скриптом
([examples/startup.txt](examples/startup.txt)) показывает то же
самое, но без участия пользователя — каждая строка скрипта
печатается как будто её ввели, сразу за ней — результат, ошибочные
строки (`not-a-real-command`, незакрытая кавычка) не прерывают
выполнение:

```
[config] vfs_path = examples/vfs.csv
[config] log_path = examples/shellemu_log.xml
[config] script_path = examples/startup.txt
[config] config_path = None
VFS:~$ ls -la /tmp
[stub] command=ls args=['-la', '/tmp']
VFS:~$ cd "My Documents"
[stub] command=cd args=['My Documents']
VFS:~$ not-a-real-command
not-a-real-command: command not found
VFS:~$ ls "unterminated
parse error: missing closing quote: "
VFS:~$ exit
```

Реальная логика `ls`/`cd` и остальные команды появятся на Этапе 4
— пока это заглушки для проверки парсера, REPL-цикла и, теперь,
конфигурации и логирования.
